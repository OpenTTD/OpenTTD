# Prismatic × OpenTTD Embedded MCP Server (research-only)

A **RESEARCH-ONLY**, compile-gated, loopback-only [Model Context Protocol](https://modelcontextprotocol.io)
server embedded inside this personal OpenTTD research fork. It exposes live OpenTTD internal state to
MCP clients (Claude Code, MCP Inspector, the Prismatic platform) over HTTP+JSON-RPC, pinned to the
stable **2025-11-25** spec. It is **not** part of upstream OpenTTD and is never network-exposed.

> Status: a real, compiling, connectable read-only vertical, plus approval-gated mutations: every
> game command whose parameters convert from JSON is a tool `openttd.cmd.<Name>`, derived from the
> command table (catalogue: `openttd://commands`), the company AIs are `openttd.ai.*`, every Script
> API function is `openttd.api.Script<Class>.<Function>`, and `game.set_pause` stays. Each mutation
> goes through a two-phase approval bound to its exact arguments (`openttd.decision.submit` or the
> tool → console `prismatic_mcp approve <id>` → posted through the command system) — see
> `08-tool-catalog.md`. The determinism A/B passed (`determinism-ab.md`).
> The native GUI Control Center window, per-client company scoping, SSE and full conformance
> evidence are **staged** — see `05-implementation-plan.md` for the honest per-phase status.
> Nothing here is a mock: the resources return live pool state over real HTTP, and a mutation is a
> real, replay-safe command execution.

## Build

```bash
cmake -S . -B build-mcp \
  -DOPTION_RESEARCH_INSTRUMENTATION=ON \
  -DOPTION_PRISMATIC_MCP_SERVER=ON
cmake --build build-mcp --target openttd -j$(sysctl -n hw.ncpu)
```

`OPTION_PRISMATIC_MCP_SERVER` defaults OFF and **requires** `OPTION_RESEARCH_INSTRUMENTATION=ON`
(configure fails loudly otherwise). When OFF, none of the module is compiled — zero footprint.
The system compiler is used; only a macOS Command Line Tools install older than Xcode 15 needs
Homebrew LLVM (`CC`/`CXX`), see ADR 0006 and [`../tooling.md`](../tooling.md) "Troubleshooting".
`tools/gate.sh research` and the research CLI's `research-mcp` profile build the same thing.

## Run

Start OpenTTD (GUI or dedicated), then in the in-game console (backtick `` ` ``):

```
prismatic_mcp start          # binds 127.0.0.1:8731, prints the bearer token
prismatic_mcp status         # running/endpoint/counters (never prints the token)
prismatic_mcp token          # prints the bearer token (local operator only)
prismatic_mcp rotate         # new token, invalidates the old one
prismatic_mcp approvals      # pending approvals; then approve <id> or deny <id>
prismatic_mcp decisions      # the provenance trace (decisions [n])
prismatic_mcp stop
```

## Connect (any MCP client, or curl)

```bash
TOKEN=<token from 'prismatic_mcp token'>
curl -s http://127.0.0.1:8731/mcp \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'

curl -s http://127.0.0.1:8731/mcp -H "Authorization: Bearer $TOKEN" \
  -d '{"jsonrpc":"2.0","id":2,"method":"resources/read","params":{"uri":"openttd://game/state"}}'
```

Bearer token via a header only — never in the URL. The endpoint refuses any request carrying an
`Origin` header (anti-DNS-rebinding) and any non-loopback connection.

## The toolbar menu (in the game)

A research build adds one button to the main toolbar, after the help button: a prism drawn in the
base set's palette (no sprite of its own). Its dropdown is one table,
`src/prismatic_mcp/prismatic_mcp_menu.cpp` (`ITEMS`), and every row does one of:

| Action | What a click does |
|---|---|
| `console` | runs a console command (`prismatic_mcp status`, `start`, `approvals`, `decisions`) and shows the console |
| `browse` | opens a hub page: `/`, `/viz` (World view), `/docs` (Swagger), `/graphql/schema`; base `$PRISMATIC_HUB_URL`, else `http://127.0.0.1:8790` |
| `ask` | "Ask the planner...": the typed sentence becomes a request of kind `ask` |
| `request` | a request of a fixed kind (`serve_here`, `plan_rail`, `watch`) for the tile under the main view's centre |
| `toggle` | calls an MCP tool with a boolean it flips (`openttd.input.yield {paused}`), shown checked |

Over MCP the same table is `openttd://ui/menu` (every row, its action and target, the switches'
state), `openttd.ui.menu.run {index, text?}` runs a row as a click does, and `openttd://ui/requests`
lists every request `{id, kind, text, tile, x, y, date, answered, answer}`. Any client answers
one with `openttd.ui.requests.answer {id, answer}`; the answer is recorded and shown in the game
as a news item. `tools/research/mcp-panel/rhai/ask_relay.rhai` answers kind `ask` through the
panel's `/api/intent`; `tools/research/mcp-human` answers the other kinds. Requests and switches
are local to the process and never change the game. The button is absent from a build without
`OPTION_PRISMATIC_MCP_SERVER`; on a split toolbar it is absent too (upstream's rows are kept).

For playing on official public servers, use the unmodified client instead:
[`../vanilla-client.md`](../vanilla-client.md).

## Boundaries

Not an official OpenTTD feature. No upstream PR/issue. No public bind, no unauthenticated access, no
token in logs/cfg/URL, no raw memory/pointer/filesystem exposure, no game-state mutation outside
the approval-gated command path. See `02-threat-model.md` and the ADR.
