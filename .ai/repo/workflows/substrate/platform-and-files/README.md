# Platform and files

Read at f8b1d52e80.

## Purpose and ownership

Owns everything between the game and the host: per-OS `main()` and helpers (`src/os/macosx/`,
`src/os/unix/`, `src/os/windows/`), where files are looked up (`Searchpath` x `Subdirectory`,
tar archives, `FileScanner`), the save/load file browser (`fios`), the ini reader/writer shared
by settings, hotkeys, windows and base sets, the driver factory registry (video, sound, music),
crash handling, thread start-up, the opt-in survey and signed social-integration plugins. The
driver implementations live in [core loop](../core-loop/README.md) (`src/video/`) and their own
directories; the setting tables that use the ini code are [settings](../settings/README.md); the
version strings (`src/rev.h`) are generated by [build](../build-and-packaging/README.md). No fork
code here: `git log --oneline upstream/master..HEAD -- src/os 'src/fileio*' 'src/ini*' 'src/driver.*'`
is empty.

## Entry points

- `src/os/macosx/osx_main.cpp:main`, `src/os/unix/unix_main.cpp:main`,
  `src/os/windows/win32_main.cpp` - validate argv as UTF-8, install the crash handler
  (`CrashLog::InitialiseCrashLog`), seed, then `src/openttd.cpp:openttd_main`.
- `src/fileio.cpp:DeterminePaths` - fills `_searchpaths` (`DetermineBasePaths`), picks the
  config directory and `_personal_dir`, creates the personal subdirectories and
  `content_download/`, and sets `_config_file`, `private.cfg`, `secrets.cfg`, `openttd.log`.
- `src/fileio_type.h:Searchpath`, `src/fileio_type.h:Subdirectory` - lookup order and content
  kinds; `src/fileio.cpp:FioFOpenFile` / `FioFindFullPath` walk `_valid_searchpaths`, then tars.
- `src/fileio.cpp:FileScanner::Scan`, `src/fileio.cpp:TarScanner::DoScan` - content discovery
  (base sets, NewGRFs, scripts, scenarios, plugins); `src/tar_type.h:TarFileListEntry`.
- `src/fios.cpp:FiosGetSavegameList`, `src/fios.cpp:FileList::BuildFileList`,
  `src/fios.cpp:FiosNumberedSaveName` (autosave names), `src/fios_gui.cpp:ShowSaveLoadDialog`.
- `src/ini_load.cpp:IniLoadFile::LoadFromDisk` and `src/ini.cpp:IniFile::SaveToDisk`;
  `src/ini_type.h:IniGroupType` (variables, list, sequence groups).
- `src/driver.cpp:DriverFactoryBase::SelectDriver` - the `-v`/`-s`/`-m` (or `[misc]
  videodriver`, `sounddriver`, `musicdriver`) choice; `src/driver.cpp:GetDriverParam` reads the
  `name:key=value,flag` options.
- `src/crashlog.cpp:CrashLog::MakeCrashLog` with per-OS subclasses
  (`src/os/macosx/crashlog_osx.cpp:CrashLogOSX`, `crashlog_unix.cpp`, `crashlog_win.cpp`).
- `src/thread.h:StartNewThread` - the only way the engine starts threads.
- `src/social_integration.cpp:SocialIntegration::Initialize`,
  `src/signature.cpp:ValidateSignatureFile`, `src/library_loader.h:LibraryLoader`;
  `src/survey.cpp:SurveyOpenTTD` and siblings build the survey and crash-log JSON.

## Lifecycle

- Start: `openttd_main` parses options (`-c` config file, `-x` do not save config, `-X` local
  paths only, `-D` dedicated, `-f` fork, `-v/-s/-m/-b` drivers), then `DeterminePaths`, the
  base-set tar scan, `LoadFromConfig(true)` (startup settings: drivers, language),
  `InitializeLanguagePacks`, the base-set scan, and selects the blitter, video, sound and music
  drivers in that order; `-D` forces `dedicated` video, `null` sound/music and the `null` blitter.
- Paths: without `-c`, the config directory is wherever `openttd.cfg` is found on the search path,
  else the first of personal, binary, working, shared, installation dir (XDG on Linux). With
  `-c <file>`, the file's directory becomes the working-dir search path, the config directory
  and `_personal_dir`.
- Running: the [core loop](../core-loop/README.md) pumps the drivers; `IniFile::SaveToDisk`
  rewrites config, hotkey and window files.
- Crash: a signal (SIGSEGV, SIGABRT from an assert, ...) runs `MakeCrashLog` once: crash log
  `crash<UTC timestamp>.json.log`, a minidump when breakpad is linked, a `.sav` and a screenshot,
  all in `_personal_dir`, then `_Exit(2)`. Normal stop: `DriverFactoryBase::ShutdownDrivers`.

## Invariants

- **[verified]** Lookup order is the `Searchpath` enum order, de-duplicated; tar members are only
  found for reads and by their lower-cased path (`src/fileio.cpp:FillValidSearchPaths`,
  `src/fileio.cpp:FioFOpenFile`).
- **[verified]** `-c <file>` moves the whole personal directory to the file's folder: saves,
  autosaves, `content_download/`, `openttd.log` and crash files go there
  (`src/fileio.cpp:DeterminePaths`, `src/crashlog.cpp:CrashLog::CreateFileName`).
- **[verified]** Autoprobe tries priorities 10 down to 1 and never a priority-0 factory, so the
  `null` video driver and, in a GUI build, `dedicated` are reachable only by name
  (`src/driver.cpp:DriverFactoryBase::SelectDriverImpl`, `src/video/null_v.h`).
- **[verified]** A named driver that fails to start is a `UserError`; only autoprobe falls
  through. A hardware-accelerated video probe leaves `hwaccel.dat` until
  `MarkVideoDriverOperational`, and the next start skips acceleration if it is still there.
- **[verified]** Factories register by static construction into a map keyed type+name and assert
  on duplicates (`src/driver.cpp:DriverFactoryBase::DriverFactoryBase`), so which drivers exist
  is decided by which files the build compiles (ADR 0022, ADR 0027).
- **[verified]** `IniFile::SaveToDisk` writes `<file>.new` and renames it over the target.
- **[verified]** `src/thread.h:StartNewThread` names the thread, calls `CrashLog::InitThread` and
  turns an escaped exception into `FatalError`.
- **[verified]** A plugin library loads only with a valid `<file>.sig` unless the build sets
  `OPTION_ALLOW_INVALID_SIGNATURE` (`src/signature.cpp:ValidateSignatureFile`).
- **[supported]** File lookup, ini parsing and the OS layer run outside the game state; nothing
  here may be consulted by a command handler (ADR 0016; `docs/desync.md`).

## Extension points

- New content kind: a `Subdirectory` value with its folder name in `_subdirs` in
  `src/fileio.cpp`, added to the `default_subdirs` list in `DeterminePaths` if it lives in the
  personal dir, and a `FileScanner` subclass for discovery.
- New driver: a `DriverFactoryBase` subclass with a static instance, listed with `add_files(...
  CONDITION <lib>_FOUND)` in its directory's `CMakeLists.txt`; pick a priority against the
  existing ones (`git grep -n 'DriverFactoryBase(Driver::Type' -- src`).
- New OS hook: declare it in a shared header and implement it in `src/os/windows/win32.cpp`
  and `src/os/unix/unix.cpp` (also built on macOS), moving the Cocoa variant into
  `src/os/macosx/macos.mm` behind `WITH_COCOA` where it differs (compare `FiosGetDiskFreeSpace`,
  `GetClipboardContents`, `OSOpenBrowser`).
- New ini consumer: subclass `src/ini_type.h:IniLoadFile` for read-only tools; `IniFile` for
  files the game writes.

## Traps and forbidden operations

- macOS: `UNIX` is also true there, so `src/os/unix/unix.cpp` and `library_loader_unix.cpp` build
  on Apple while `crashlog_unix.cpp`/`survey_unix.cpp` do not (`src/os/unix/CMakeLists.txt`).
  Paths come from `CocoaSetApplicationBundleDir`/`CocoaGetAppSupportDir`
  (`src/os/macosx/macos.mm`); there is no XDG (`src/stdafx.h:USE_XDG`).
- `src/ini_load.cpp` is also compiled into `settingsgen` (a host tool): keep it free of game
  globals; the file opening is the virtual `IniLoadFile::OpenFile`.
- `IniLoadFile::LoadFromDisk` reads with a 1024-byte buffer, so a longer line is split into two.
- A headless research run needs a base set on its search path: without one it hangs on macOS
  (knowledge `macos-missing-baseset-hangs-headless-runs`). Pass `-x` so a run never rewrites the
  config it was given, and a fresh `-c` per run so its saves and crash logs stay in its bundle.
- `-D` also sets `-d net=4`, which floods stdout; a tool parsing output passes a later
  `-d net=<n>`, since options apply in order.
- `-f` (`src/dedicated.cpp:DedicatedFork`) is UNIX-only and redirects stdout/stderr to
  `openttd.log`: never use it under a supervising script that reads stdin/stdout.

## Tests and validation

- No Catch2 target covers this area.
- Regression cases start the real binary with `-vnull:ticks=30000 -snull -mnull` through
  `cmake/scripts/Regression.cmake`: the only automated exercise of search paths, ini loading and
  named driver selection with parameters.
- Tier: `tools/gate.sh change`; a change to `src/os/` compiles only for its OS, so name the
  platforms that were not built (`project.never-report-unrun-validation-as-pass`).
- Debug: `-d misc=3` prints every search path, `-d misc=1` the config and personal directories,
  `-d driver=1` each probe and its error; `openttd -h` lists the compiled drivers and base sets.
- Fork headless runs: `tools/research/research run` starts `-D -x -g -G <seed> -c <cfg>`
  (`tools/research/research`), `tools/research/mcp-live-check` the same with `-d net=1`.

## Decisions, rules and knowledge

- ADR 0022 (drivers chosen at runtime from a factory registry), ADR 0027 (conditional sources),
  ADR 0028 (base sets come from search paths), ADR 0016 (no host state in game logic).
- Rules: `project.never-report-unrun-validation-as-pass`, `project.research-code-is-gated-and-labelled`.
- Knowledge: `macos-missing-baseset-hangs-headless-runs`, `dedicated-server-stdin-startup-race`,
  `fixed-loopback-ports-collide`, `the-config-flag-moves-the-personal-directory`,
  `the-null-video-driver-never-drains-the-main-thread-queue`. Upstream: `docs/directory_structure.md`.

## Typical tasks

- To find why a file is not found: run with `-d misc=3`, compare against
  `docs/directory_structure.md`, check case (tars are lower-case) and `-X`.
- To isolate an experiment: give it its own `-c <dir>/openttd.cfg` plus `-x`, put or link
  `baseset/` next to it or rely on the binary dir; collect `crash*` files from that dir.
- To add a driver option: read it with `GetDriverParam`/`GetDriverParamInt` in the driver's
  `Start`, document it in the factory description, validate with `tools/gate.sh change`.
- To change how a crash is reported: edit `src/crashlog.cpp` (shared) and each
  `src/os/*/crashlog_*.cpp`; trigger with an `assert` in a debug build and read the `.json.log`.
